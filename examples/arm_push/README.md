# ARM Push — Integration Test

End-to-end test for the ADK ARM image-push feature ([#88741](https://github.ibm.com/WatsonOrchestrate/wo-tracker/issues/88741)).

## Contents

```
examples/arm_push/
├── agent-image/
│   ├── Dockerfile              # Minimal Alpine-based agent image
│   ├── agent.py                # Stub Flask agent with /health endpoint
│   └── requirements.txt        # flask>=3.0.0
├── Dockerfile.trm-arm-local    # Lightweight TRM build for local ARM testing
├── build-trm-local.sh          # Builds image + hot-swaps TRM in dev-edition stack
├── test_arm_push.sh            # Idempotent end-to-end test script
└── local-arm-trm.yml           # ⚙️ Auto-generated by build-trm-local.sh (gitignored)
```

> **`local-arm-trm.yml`** is generated on first run from the installed default `compose-lite.yml`
> with the following changes applied automatically:
> - TRM image swapped to the locally-built `tools-runtime-manager:<branch>` with `pull_policy: never`
> - `arm-registry` Docker Registry v2 service added (port 5000) as a depends_on for TRM
> - ARM registry env vars injected into TRM (`REGISTRY_HOST`, `REGISTRY_TYPE`, etc.)
> - OpenSearch knowledge service and its dependencies removed (not needed for ARM push testing)
>
> If the file already exists and contains the current branch's image tag it is **skipped**.
> Delete it to force regeneration (e.g. after upgrading the installed `orchestrate` package).

## Prerequisites

- `docker` with the dev-edition stack running
- `tools-runtime-manager` repo cloned and checked out at `aaron-local-validate-epic-arm-de-pe` branch

## Local ARM Server Setup & Step-by-Step Validation

### Step 1: Build the ARM TRM Image & Restart Orchestrate Server

From `wxo-clients/examples/arm_push/`:

```bash
bash build-trm-local.sh \
  --trm-dir /path/to/tools-runtime-manager \
  --trm-branch aaron-local-validate-epic-arm-de-pe \
  --env-file /path/to/dev-edition/custom.env \
  --wxo-cmd /path/to/orchestrate
```

`build-trm-local.sh` will:
1. Run preflight checks (CLI reachable, `python3` available)
2. Auto-generate `local-arm-trm.yml` on first run (skipped if already up-to-date)
3. Compile the TRM Go binary for the target arch and build the Docker image
4. Restart the orchestrate server with `--preview-arm`, `--compose-file local-arm-trm.yml`, and `--env-file`

To use a pre-existing compose file instead of the auto-generated one, pass `--compose-file <path>` explicitly.

---

### Step 2: Run the Automated Validation Test Script

Execute the test script directly by passing your server URL and CLI executable:

```bash
# Run both S3 and Registry tests (default)
bash test_arm_push.sh \
  --server-url http://localhost:8080/api/v1 \
  --wxo-cmd /path/to/orchestrate

# Or run only the S3 upload test
bash test_arm_push.sh s3 \
  --server-url http://localhost:8080/api/v1 \
  --wxo-cmd /path/to/orchestrate

# Or run only the Registry test
bash test_arm_push.sh registry \
  --server-url http://localhost:8080/api/v1 \
  --wxo-cmd /path/to/orchestrate
```

---

### Step 3: Run the ADK CLI Commands Manually (Step-by-Step)

If you want to run the exact manual commands yourself without using `test_arm_push.sh`:

#### 3A. S3 Presigned URL Method:

```bash
# 1. Build and export the local test agent Docker image
docker build -t arm-test-agent:latest examples/arm_push/agent-image
docker save arm-test-agent:latest -o /tmp/arm-test-agent.tar

# 2. Push image archive to ARM via S3 method
FEATURE_ARM_PUSH=true ARM_SERVER_URL=http://localhost:8080/api/v1 orchestrate runtime push-image \
  --image /tmp/arm-test-agent.tar \
  --name arm-test-agent \
  --type agent \
  --tag v-20261007-01 \
  --source-type s3 \
  --description "Manual S3 validation"

# 3. Clean up the exported archive
rm -f /tmp/arm-test-agent.tar
```

#### 3B. Registry Method:

```bash
# Bind an external OCI image reference directly into ARM
FEATURE_ARM_PUSH=true ARM_SERVER_URL=http://localhost:8080/api/v1 orchestrate runtime push-image \
  --image "docker.io/library/hello-world:latest" \
  --name arm-test-agent-registry \
  --type agent \
  --tag v-20261007-01 \
  --source-type registry \
  --description "Manual registry validation"
```

## dev-conn usage

```bash
export ARM_SERVER_URL=https://<dev-conn-host>/api/v1

```

## What the script does

| Step | Description |
|------|-------------|
| 1 | Builds the `agent-image/` Dockerfile into a local Docker image |
| 2 | Exports the image to a `.tar` archive (`/tmp/arm-test-agent.tar`) |
| 3 | **S3 push** — calls `orchestrate runtime push-image --source-type s3`, which: obtains a presigned URL from ARM, streams the archive to S3, then calls ARM to copy into the cluster registry |
| 4 | **Registry push** — calls `orchestrate runtime push-image --source-type registry` to bind a public OCI reference directly |
| 5 | Cleans up the local tar archive |

## Idempotency

Each run generates a timestamp-based tag (e.g. `v-20261005-143022-s3`) so repeated runs never collide with an existing tag. The workload name is fixed (`arm-test-agent`) so ARM accumulates versions rather than creating duplicates.

## Configuration & CLI Options

The test script accepts command-line arguments as well as environment variables. Command-line flags take precedence.

```bash
# Run with CLI arguments:
bash examples/arm_push/test_arm_push.sh --mode s3 --server-url http://localhost:8080/api/v1 --workload-name my-agent

# Or run with environment variables:
export ARM_SERVER_URL=http://localhost:8080/api/v1
bash examples/arm_push/test_arm_push.sh s3
```

| CLI Option | Environment Variable | Default | Description |
|------------|----------------------|---------|-------------|
| `--mode` / positional | `MODE` | `all` | Push mode: `s3`, `registry`, or `all` |
| `--server-url` | `ARM_SERVER_URL` | `http://localhost:8080/api/v1` | ARM server base URL |
| `--workload-name` | `WORKLOAD_NAME` | `arm-test-agent` | Workload name registered with ARM |
| `--workload-type` | `WORKLOAD_TYPE` | `agent` | One of: `agent`, `mcp_toolkit`, `guardrails`, `eval` |
| `--archive-path` | `ARCHIVE_PATH` | `/tmp/arm-test-agent.tar` | Local path for the exported Docker tar archive |
| `--source-image` | `SOURCE_IMAGE` | `docker.io/library/hello-world:latest` | OCI image reference for registry push mode |
| `--wxo-cmd` | `WXO_CMD` | `orchestrate` | CLI binary name or path |
| `--skip-context-check`| `SKIP_CONTEXT_CHECK` | `false` | Skip checking/switching Docker context |
| `n/a` | `FEATURE_ARM_PUSH` | `true` | Must be `true` to enable the CLI commands |

## Confirming the image works end-to-end

After a successful push, verify the deployed workload responds correctly:

```bash
# Liveness check
curl -s http://<workload-host>/health

# Chat invoke — should return {"reply": "Hello, World!"}
curl -s -X POST http://<workload-host>/chat \
     -H "Content-Type: application/json" \
     -d '{"message": "say hello"}' | jq .reply
```
